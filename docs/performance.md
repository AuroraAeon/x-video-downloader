# 1.2.0 性能审查与测量

日期：2026-09-15。基线：Git tag `v1.1.1`。新版本：1.2.0。

## 发现与修复

| 环节       | 旧实现的问题                                                                                      | 1.2.0 的处理                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 页面采集   | 100ms 调度；频繁 DOM 变化使图标重复生成并重复计算播放器布局                                       | 16ms 合并调度；UI 状态签名去重；仅播放器相关结构/尺寸变化重算布局                                             |
| 缺失元数据 | 固定等待 900ms 才启动详情回退；嵌入接口网络等待占用后台全局任务队列                               | 首次等待缩到 150ms；嵌入请求与任务修改队列分离，保留正常鉴权边界                                              |
| 多媒体排队 | 一条 FIFO；滚走后活动请求继续占用队头；每次创建 Worker                                            | 两条队列、当前可见优先、取消无订阅探测、复用 Worker；显式下载等待的探测不会被滚动取消                         |
| 候选枚举   | 清晰度逐个串行，音频后才检查视频                                                                  | 同一媒体最多三候选同时处理，轨道有界并行；整个媒体最多四个网络读取并发                                        |
| 底层读取   | `computePacketStats`/`computeFrameRateMetrics` 虽然用 metadataOnly，但 UrlSource 仍会预取视频负载 | Mediabunny 标准 CustomSource/CustomPathedSource + 32 KiB 块 Range，按字节跳过无关负载，共享相同块的进行中请求 |
| 缓存       | 摘要仅存在后台内存；候选仅存在离屏文档，休眠/关闭后重新下载                                       | storage.session 保存摘要十五分钟、候选两分钟；最多 128 条、持久化预算 4 MiB，浏览器结束后不保留               |
| 展示       | 等全部输入完成才出现信息                                                                          | 页面已有尺寸及早显示为“已知、确认中”；已完成候选逐步反馈，完成前不承诺最高画质                                |
| 生命周期   | 失败的 CustomPathedSource 根请求释放可能产生未处理拒绝                                            | 根 Source 同步解析、子资源明确初始化、引用保持至 Input 完成，再统一取消并释放                                 |

## 精度与访问约束

没有用降低采样数或忽略候选换取提速：音频仍测量 96 个包，视频仍测量 64 帧；音视频编码、码率、采样率、声道数、候选排序逐项对比通过。没有假设最高 MP4 一定高于 HLS，也没有把某条默认音轨当作最高音质。

媒体内容解析继续由锁定版本 Mediabunny 完成，未自写 MP4/HLS 解码器。自定义层只负责有界、安全的网络字节读取。每个输入探测上限 16 MiB，拒绝不支持 Range 且超过 4 MiB 的视频响应，完整播放清单上限 1 MiB；参数超出预算时明确显示候选不可用，不谎称已完整确认。

探测请求不做反复重试：网络 8 秒无进展、每输入 12 秒、后台探测任务 20 秒上限。正式下载仍保留原有网络重试与逐候选降级；不会无限保持后台运行。请求只能访问允许的 X CDN 路径，仍拒绝重定向、加密清单及跨域凭证。

## 固定延迟基准

Chrome for Testing 145，Playwright 1.63.0。独立浏览器配置，localhost HTTPS 服务将每次响应延迟固定为 80ms。样例包含两个 MP4 档位、一个 HLS 视频以及两条不同码率音轨。每个构建测量三次 Worker 探测，中位数如下；三视频 UI 是同配置下的端到端单次测量。该测试不使用浏览器假下载替代实际扩展执行。

| 指标                                 |                    1.1.1 |           1.2.0 |
| ------------------------------------ | -----------------------: | --------------: |
| 单媒体完整探测中位时间               |                 1694.9ms |         571.0ms |
| 单媒体读取字节                       |                1,891,958 |         267,661 |
| 单媒体请求数                         |                       18 |              18 |
| 三媒体冷启动全部信息完成             |                 5198.9ms |        1169.6ms |
| 三媒体热缓存全部信息完成             |                  109.0ms |          20.9ms |
| 关闭离屏文档并停止后台后全部信息完成 |                 5182.2ms |          25.7ms |
| 停止后台后重新读取 CDN               | 54 请求 / 5,675,874 字节 | 0 请求 / 0 字节 |

完整探测快约 66%，数据量减少约 86%，三媒体冷启动显示快约 77%。冷启动请求数量未减少，改进来自读取量和依赖路径并行化；只有缓存命中消除了重复请求。

`scripts/performance.mjs` 在设置 `XVD_COMPARE` 时会严格对比全部候选与数值，要求探测至少快 25%、读取量至少下降 60%、三媒体显示至少快 35%，并断言后台重启不重新读取 CDN。原始记录在本地 `output/perf/baseline-full.json`、`optimized-full.json`。

复现时将 v1.1.1 构建放在独立目录，然后使用相同浏览器和 `XVD_LATENCY`：

```powershell
$env:XVD_EXTENSION='output/perf/baseline-1.1.1'
$env:XVD_PERF_NAME='baseline-full'
pnpm test:performance
Remove-Item Env:XVD_EXTENSION
$env:XVD_PERF_NAME='optimized-full'
$env:XVD_COMPARE='output/perf/baseline-full.json'
pnpm test:performance
```

## 真实 X 样例

对同一公开帖子 `1001551623938805763`，正常浏览器窗口加载后，控件出现至完整信息确认：旧构建 4899ms，新构建 320ms。视频与音质结果相同，视频和独立 M4A 下载、文件检查通过。

真实网络测量是单次顺序采样，CDN、代理、X 页面加载和预热均可能影响结果，不能将这个约 93% 的数字承诺给所有帖子。固定延迟基准才用于比较算法性能。新版本无法消除 X 自身导航耗时，本次导航仍约 8 秒。

## 项目独立性

此前扩展已拥有自己的 `.git`、依赖和远程仓库，并未依赖 MediaCrawler 的 Python 代码；不合理之处是物理路径混放，容易误操作或误解所有权。源码、`.git`、测试、依赖和产物现已全部移到 `F:\x-video-downloader`。旧位置只保留 `dist` junction 和迁移说明，保证已安装扩展的路径继续有效，不维护第二份源码。

增加固定 pnpm 工具版本、Node 版本约束、独立 AGENTS.md 和 push/PR CI；发布产物继续通过 manifest/版本/文件清单/SHA-256 校验，源码无 MediaCrawler 运行依赖。
