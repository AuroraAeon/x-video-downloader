Privacy policy

Product: X Video Downloader (browser extension) · Version: 1.3.0 · Effective: 2026-09-24 · Data controller: the maintainer of the AuroraAeon/x-video-downloader repository.

Short version

  • The extension transmits no data to us or to any third-party service we control. We have no server, no account system and no endpoint to receive anything.
  • There is no telemetry, no analytics, no crash reporting.
  • Nothing is collected to a server. Ever.
  • The only stored data is your own task history, in your own browser, via chrome.storage, capped at 60 finished entries. You can clear it in one click.
  • No cookies and no credentials are read or written. Media requests never carry X session authentication headers.
  • Downloaded files go to your Chrome download manager, in a destination you control.

1. Scope

This policy covers the X Video Downloader browser extension (Manifest V3, Chrome 116 or newer) distributed as a GitHub release archive and submitted to the Chrome Web Store and Microsoft Edge Add-ons. It does not cover X Corp.’s own services, your browser vendor’s sync or download history, or any other site you visit. The extension is independent and is not affiliated with, endorsed by, or sponsored by X Corp.

2. No data is transmitted anywhere by the extension

All runtime code is bundled inside the extension package. There is no backend, no API key, no remote script, no eval, no remote module loading and no native messaging. Because there is no service of ours to receive data, no usage information can leave your machine through the extension:

  • No telemetry. Installation counts, which posts you opened, which media you inspected, which files you downloaded, whether a task failed — none of it is reported to us.
  • No analytics or tracking. No analytics SDK, no beacons, no fingerprinting, no advertising identifiers.
  • No crash or error reporting. Errors are surfaced to you in the popup, not shipped to a collection service.
  • Nothing is collected to a server. There is no server.
  • The content security policy restricts extension pages to script-src 'self'; object-src 'none'; worker-src 'self' and limits connections to connect-src 'self' https://video.twimg.com https://cdn.syndication.twimg.com, so the packaged code cannot phone home to an arbitrary host.
  • Messages from the page carry media records only and cannot start a download by themselves; only a trusted action on the content-script UI can.

3. Network requests the extension makes

The only outbound traffic is the requests required to read the post you are already viewing and to fetch the media you asked to download. Host permissions are exactly:

Host Purpose Data sent
https://x.com/* Show the button and read media data already present in that page. Ordinary page requests from your own browser session.
https://video.twimg.com/* Read media manifests and audio/video data; bounded Range reads of headers and sample tables during inspection. The CDN URL you are downloading, with X session authentication headers explicitly not attached.
https://cdn.syndication.twimg.com/* Public embed metadata fallback for videos in view. The public media identifier.

Inspection is bounded and cancellable: two probe queues prioritise videos in view, at most four requests run concurrently per media item, and 32 KiB Range reads fetch only what is needed rather than prefetching a video body. Automatic inspection creates no files.

4. Local task records — the only stored data

Task history is written to your browser through chrome.storage, using the storage permission. A record may contain:

  • the post ID;
  • the author handle;
  • the media URL;
  • the output filename.

This data never leaves the browser. It exists so the popup can show your tasks with the quality actually obtained and the reason for any limitation or fallback, and so you can cancel or retry them. Finished records are capped at 60 entries; when a new finished task pushes the list past that, the oldest records are dropped automatically.

How to clear it

  1. Click the X Video Downloader toolbar icon and use the clear finished tasks control (the trash icon in the popup header). That removes the stored task records.
  2. Or remove the extension in chrome://extensions (edge://extensions in Edge) — its local storage goes with it.
  3. Or, in Edge/Chrome, clear the browser’s own extension site data if you want a belt-and-braces removal.

Clearing tasks does not delete downloaded files and does not clear Chrome’s own download history. It only removes the extension’s records. To delete media, use your file manager; to clear Chrome’s list, use Chrome’s downloads page.

5. In-session cache

To avoid re-probing the same media, the extension keeps short-lived entries inside the browser session: display summaries for 15 minutes and download candidates for 2 minutes. These survive the background service worker sleeping and the offscreen document closing, which is why re-opening a video is fast.

  • Signed CDN URLs may therefore be held in memory in-session for a short time. They are never persisted together with credentials.
  • If a signed URL changes, the cached entry is invalidated and re-fetched.
  • The cache does not cross browser sessions.
  • No authentication data of any kind is stored in it.

6. Cookies and credentials

The extension does not request the cookies permission and does not request the debugger permission or any host-wide grant. It reads no cookies, no session tokens, no passwords and no authentication headers, and it stores none. It cannot and does not export login state; installing it requires no sign-in, and no cookie has to be copied. Media requests never include X session authentication headers. The extension has no mechanism to bypass login walls, protected accounts, regional restrictions or platform challenges: it can only handle media already obtainable, or normally obtainable, under your existing access conditions.

7. Where downloaded files go

Files are saved by the Chrome download manager, using the downloads permission, so the destination directory follows your own Chrome settings and is entirely user-controlled. Filenames look like x_author_1001551623938805763_1_480x360.mp4. During media processing temporary data lives in OPFS storage belonging to the extension and is deleted once Chrome finishes the save; if the disk is full the task stops with an error rather than silently writing elsewhere. Nothing is uploaded after the file exists.

8. What is never collected

No personal identifiers, no names or email addresses, no X credentials or cookies, no browsing history, no list of the pages you visit beyond the tasks you started, no keystrokes, no screenshots, no device or hardware identifiers, no IP address harvested by us, no location, no advertising or persistent identifier, no audio/video content sent anywhere. There is no account, so there is no profile to build.

10. Children’s privacy

The extension is a general-purpose download utility that works with X. It collects no personal information from anyone, including children, and transmits nothing, so it gathers no data that could be subject to COPPA or similar regimes. Using X and downloading content from it remains subject to X’s own terms and age requirements.

11. Retention, deletion and your rights

Retention is local and short by design: task records stay until you clear them or until the 60-finished-entry cap discards them; the probe cache lasts minutes inside one session; downloaded files stay wherever you put them until you delete them. Because we never receive data, we cannot disclose, correct or export data we do not hold — and there is nothing for a third party to request from us. To exercise deletion, clear the task list or uninstall the extension; both act immediately, on your own device, with no request to us needed.
