功能

视频上的画质选择菜单

视频画面内部角落是 28px 按钮配 16px 图标。点击展开视频/音频菜单。菜单支持键盘选择、按 Escape 关闭，点击外部也会关闭。

下载前就有明细

在播放器之外的正常文档流位置显示分辨率与帧率，以及音频编码、估计码率、采样率和声道数。看到这些数值不需要先下载。

任务弹窗

点击工具栏图标可查看任务列表、实际取得的画质、限制或降级原因，并取消或重试任务，还可以直接跳到 Chrome 自身的下载页面。

文件由 Chrome 保存

下载通过 Chrome 下载管理器完成，保存位置遵从你的 Chrome 设置，完全由你决定。文件名示例 x_author_1001551623938805763_1_480x360.mp4。

画质与音频行为

「最高」是怎么定的

「最高」指 X 提供且你当前能取得的版本，不是上传原片。视频候选按实际像素、帧率、同编码码率排序，同档优先直链 MP4。播放器当前清晰度、预览图尺寸和 original_info 都不直接代表可下载版本。

音频逐轨比较，并且始终无损

所有可用音轨独立比较，按码率、采样率、声道数排序；从 HLS 或 MP4 无损提取为 M4A，绝不转成有损 MP3，也不会静默丢弃配对音轨。HLS 只做无损封装，不重编码。

前缀 ≈ 表示该码率是通过编码包抽样估计得到的，单位为 kb/s、kHz、ch。这是测量结果，不是对听感的主观评分。

检查有界、可取消，并且对部分结果诚实

  • 自动检查不会创建任何下载文件，只读取必要内容。
  • 两条有界探测队列优先处理当前可见的视频；滚出视野且未被下载使用的检查会被取消。
  • 每个媒体最多四个网络请求并发；32 KiB 的 Range 块只读取必要的头部和样本表，不预取整段视频负载。
  • 全部候选仍会检查，保留音频 96 包、视频 64 帧的测量范围。
  • 检查未完成时信息栏显示「已知… · 确认中」。部分结果绝不会被标为已确认的最高画质，只有完成后才升级为最高可用结果。
  • 页面侧超过 45 秒没有结果的探测会自动重发，不会长期停在「检测中」；两条合并任务运行期间仍保留一条探测通道。

你可能感知到的吞吐限制

一次最多两个活动下载任务，其中最多一个媒体合并或音频提取，最多排队 20 个任务。同一视频的视频下载和音频下载分别去重。媒体临时数据放在 OPFS 中以控制内存，Chrome 保存完成后删除临时文件。失败候选可自动降级并保留提示；取消、磁盘问题、限流、非法地址会停止任务，而不是无限重试。

会话缓存

浏览器会话内复用十五分钟的显示摘要与两分钟的下载候选，后台 service worker 休眠和离屏文档关闭不会清空。签名 URL 改变会使缓存失效。缓存不跨浏览器会话，也不存储任何鉴权信息。

支持范围与不支持范围

下面就是产品边界，逐条来自扩展自己的声明。没有写在「支持」里的能力，请当作不支持。

支持

  • X 托管的视频。
  • 以视频文件存储的动图（GIF）。
  • 含多个视频的帖子：各自独立定位、各自下载。
  • 引用帖与转帖：通过媒体 ID、预览图及帖子链接确定归属；无法确认时不猜测。
  • 先读取网页已有的 GraphQL/SSR 数据，视频接近可视区域时读取有限媒体数据，不足时串行读取所属帖子详情和 X 自有公开嵌入接口作为后备，失败不无限重试。
  • 在当前访问条件下已经取得、或正常可以取得的媒体。
  • 关闭或离开来源页面不会取消已开始的任务；后台 worker 休眠或重启后会与离屏任务和 Chrome 下载记录对账。

不支持

  • 直播录制，以及 Spaces。
  • 外部视频网站。
  • 加密 HLS 与 DRM 内容。
  • 绕过登录、受保护账号、地区限制或平台验证挑战。
  • 取得创作者上传的原片。
  • 浏览器整体退出后从任意分片断点续传未完成的合并 —— 这类任务需要重试。
  • 有损转换，例如输出 MP3。
  • 运行时的任何后端、账号、API Key、Python 或 FFmpeg 依赖。

网站随时可能改变 DOM、接口和数据结构。扩展针对当前的站点维护；X 改版后需要更新版本。

路径 3 · 现在可用

手动：从 GitHub 发行版加载已解压的扩展

  1. 从最新发行版 下载 x-video-downloader-1.3.0.zip 并解压；同处提供 SHA256SUMS.txt 校验文件。
  2. 打开 chrome://extensions，开启右上角「开发者模式」。
  3. 点击「加载已解压的扩展程序」，选择解压后的目录 —— 即包含 manifest.json 的那个目录。
  4. 刷新已打开的 X 页面，保持原有登录状态，点击视频右上角的下载图标。

扩展安装目录需要保留。更新时把新包解压覆盖到原先加载的同一个目录，在 chrome://extensions 点击卡片上的刷新图标，确认版本为 1.3.0 后刷新 X 页面。无需重新登录；沿用同一目录可以保留扩展 ID 和本地任务记录。

权限与用途

清单申请的权限就是下面这些 —— 没有别的，也没有 <all_urls>。
权限 用途
downloads 启动、取消和跟踪扩展自己创建的下载。
storage 本地任务状态，最多保留 60 条已结束记录。
offscreen Worker 媒体处理，以及在下载完成前维持 Blob URL。
https://x.com/* 页面按钮，以及从同一页面采集媒体数据。
https://video.twimg.com/* 读取媒体清单和音视频数据。
https://cdn.syndication.twimg.com/* 可视视频的公开嵌入元数据后备来源。

不申请 cookies 权限，不申请调试器权限，不申请全站权限 ，也没有登录绕过。媒体请求不携带 X 会话鉴权头。所有运行时代码随扩展打包：没有远程脚本、没有 eval、没有远程模块加载、没有原生通信，我们也没有任何服务器可连。页面消息只传递媒体记录，不能单独触发下载。

故障排查

能看到的视频上没有按钮
刷新 X 页面 —— 内容脚本只在页面加载时接入；更新或重新加载扩展后同样要刷新页面。如果你移动过扩展目录，请从新位置重新「加载已解压的扩展程序」。
信息栏一直停在「检测中」
刷新 X 页面，或直接打开该帖子。探测有期限且会自动重发；如果 X 响应慢或拒绝请求，会明确提示失败，而不是输出猜测数据。
提示画质受限或已经降级
打开任务弹窗：里面写明实际取得的画质和原因。最高候选下载失败时会降级并保留警告；来自可能不完整来源的结果会标记限制。取消与重试也在同一弹窗完成。
X 自身要求登录，或返回 403、限流
先解决网页访问问题。扩展不绕过登录、保护账号、地区限制或平台验证，也不会在媒体请求中发送 X 会话凭据。
下载因为 429、磁盘错误或非法地址失败
这些情况会停止任务而不是循环重试。合并过程会使用临时文件直到 Chrome 保存完成，请先清理磁盘空间再重试；限流来自 X，不是来自我们。
音频选项是灰色不可点
该媒体确实没有音轨，扩展会明确说明，而不是给你一个假选项。
合并过程中关闭了浏览器
被中断的 HLS 合并需要重启后重试；不承诺从任意分片位置断点续传。
X 改版后一切都不正常了
X 可以随时改变 DOM 或接口。请先查看 发行版 是否有新版本；如果已是最新，请带上帖子链接提交 issue。
